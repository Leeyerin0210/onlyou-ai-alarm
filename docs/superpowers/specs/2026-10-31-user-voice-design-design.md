# 유저가 만드는 비서 목소리 — VoiceDesign 생성 (2026-10-31)

[2026-08-14 페르소나·음성 범위 재설계](2026-08-14-persona-voice-scope-design.md)는 유저 화면에서
VoiceDesign 목소리 생성을 뺐고, [2026-10-13 프리셋 폐지](2026-10-13-presets-removal-design.md)는
"유저 비서의 목소리"를 범위 밖으로 남겼다. 이 문서는 그 기능을 되살린다. 비서를 만드는 사람이
그 비서의 성격에 맞는 목소리를 직접 만들어 넣는다.

08-14 스펙에서 목소리 생성을 뺀 이유 셋은 이번에 이렇게 막는다.

| 08-14의 우려 | 이번 대응 |
|---|---|
| 목소리 설명 칸이 텍스트 심사를 우회하는 통로(숨소리·속삭임 등 비언어 발화) | 목소리 설명·샘플 문장을 공개 심사에 넣는다 |
| 임의 오디오 업로드로 연예인·지인 목소리 클로닝(음성권) | 기준 음성은 **서버가 VoiceDesign으로 만든 것만** 쓴다. 앱이 오디오를 올리는 길(`/voice/save_reference`)을 닫는다 |
| 유저 트래픽의 VoiceDesign 호출이 알람 선생성과 GPU를 다툼 | 지금은 무제한(남용 방지용 일일 한도만). 후속으로 보석 과금 |

## 왜

공식 비서는 고유한 목소리가 있고 유저가 만든 비서는 없다. 유저 비서의 알람은 폰 기본 TTS로
울린다. 사용자 판단: 목소리가 있고 없고의 **몰입감 차이가 너무 크다.** 그래서 공개 비서는 목소리가
필수다.

## 결정 요약

| 항목 | 결정 | 누가 |
|---|---|---|
| 입력 | 목소리 설명(300자) + 샘플 문장(약 60자, 비우면 기본 문장) | 사용자 |
| 생성 | 설명을 고치든 그대로 두든 "다시 만들기"로 다시 뽑을 수 있다 (VoiceDesign은 매번 결과가 다르다) | 사용자 |
| 후보 보관 | **최신 1개만.** 다시 만들면 이전 것은 사라진다 — 과금 유도를 위한 의도적 선택 | 사용자 |
| 샘플 음성의 용도 | 그 비서의 클로닝 기준 음성 + 상점 미리듣기 음성 | 사용자 |
| 상점 | 공개 비서는 만든 목소리를 그대로 들고 간다 (원본을 함께 쓰는 구조 그대로) | 사용자 |
| 공개 조건 | 공개하려면 목소리가 **필수** | 사용자 |
| 비공개 비서 | 목소리 선택 사항. 없으면 지금처럼 폰 기본 TTS | Claude (사용자 이의 없음) |
| 공개 심사 | 성격 세 칸 + **목소리 설명 + 샘플 문장** | 사용자 |
| 공개 후 목소리 변경 | **지금은 허용**(시연용). 바꾸면 재심사, 통과 시 쓰던 사람들도 다음 알람부터 새 목소리. 후속에서 "한 번 공개하면 변경 불가"로 바꾼다 | 사용자 |
| 생성 횟수 | 지금은 무제한. 남용 방지 일일 한도만. 후속에 보석 과금 | 사용자 (한도는 Claude) |
| 남이 만든 비서의 목소리 설명·샘플 문장 | 상점에 노출하지 않는다 (세 칸과 같은 규칙). 소리는 미리듣기로 들린다 | Claude |

## 범위

**안에:** 서버 생성·확정·심사 경로, `/voice/save_reference`·`/voice/synthesize` 폐쇄, 앱 비서 수정
화면 목소리 칸, 공개 조건, 상점 미리듣기가 유저 비서에도 동작하는지 확인.

**밖 (후속):**
- 보석으로 생성 1회마다 과금 — 생성 지점을 서버 한 함수로 모아 둬서 그때 거기만 고치면 되게 한다
- 공개 후 목소리 변경 금지
- 공식 비서 목소리를 이 경로로 다시 만드는 일 (`gen_reference_voices.py` 그대로)

**하면 안 되는 것 (실패로 본다):**
- 앱이 보낸 오디오가 기준 음성이 되는 경로가 하나라도 남는 것
- 심사를 거치지 않은 목소리 설명·샘플 문장이 공개 비서에 붙는 것
- 공개 비서가 목소리 없이 상점에 오르는 것

## 화면 (비서 수정, `PersonaEditScreen`)

위치는 "역할 (선택)"과 "태그" 사이. 순서:

1. **목소리 설명** 칸 — 300자, 기존 `CustomCounterTextField`. 예시: "예) 20대 남자, 낮고 차분한 목소리. 살짝 졸린 듯 느긋하게 말함"
2. **샘플 문장** 칸 — 약 60자. 예시는 기본 문장. 안내: "숫자·영어 없이 한글로 써 주세요. 상점에서 이 문장으로 미리듣기가 나가요."
3. **[만들기]** 버튼 (후보가 있으면 **[다시 만들기]**). 생성 중엔 로딩, 버튼 비활성.
4. **후보 플레이어** — 재생 버튼·길이. 후보는 하나뿐.
5. **[이 목소리로 정하기]** — 후보를 이 비서의 목소리로 고른다.
6. 이미 정해진 목소리가 있으면 그것도 재생할 수 있게 "지금 목소리"로 보여 준다.

규칙:
- 정하지 않고 새 후보만 만들어 보면 정해진 목소리는 그대로다.
- 다시 만들면 이전 후보는 화면·서버에서 모두 사라진다.
- 설명 칸이 비어 있으면 [만들기] 비활성.
- 공개로 저장하려는데 정해진 목소리가 없으면 저장을 막고 "공개하려면 목소리를 만들어 주세요"를 띄운다.

시안: `.superpowers/brainstorm/` 의 `voice-layout.html` A안 (참고용, 커밋 안 됨).

## 서버

### 저장소 — 기준 음성과 후보

기존 `voice_service`는 `reference_voices/{persona_id}.wav` + `{persona_id}.json({"ref_text"})`
(GCS 동일 키)을 기준 음성으로 쓴다. 이 구조를 유지한다.

후보는 별도 키에 하나만 둔다 (Claude 결정): `reference_voices/drafts/{persona_id}.wav` +
`.json({"ref_text", "voice_description", "creator_uid"})`. 새로 만들면 덮어쓴다.

### DB — `personas` 컬럼 추가 (Claude 결정)

- `voice_description TEXT` — 정해진 목소리를 만든 설명
- `voice_sample_text TEXT` — 정해진 목소리의 샘플 문장(= 기준 음성의 ref_text)

옛 `voice_prompt` 컬럼은 10-13 스펙대로 다음 릴리스 DROP 대상이라 재사용하지 않는다.
"목소리가 있는가"는 `voice_sample_text IS NOT NULL`로 판단한다(기준 음성 파일과 함께 쓰인다).
공식 비서는 기존 기준 음성 파일이 있으므로 시드에서 이 두 칸을 채운다
(`gen_reference_voices.py`의 instruct·문장). 공식 비서의 설명은 영어 instruct 그대로 들어간다 —
상점에 노출하지 않고 심사 대상도 아니라 문제없다.

### `POST /voice/design/{persona_id}` — 후보 만들기 (신규)

- 요청: `{"description": str ≤300, "sampleText": str ≤ SAMPLE_MAX_LEN | 빈 값}`
- 소유자 확인은 기존 `_require_persona_owner`(미저장 비서는 생성 중이라 허용).
- 일일 한도: 새 키 `voice-design`, 사용자당 하루 50회 (Claude 결정, 설정값). 전역 예산은 기존 `voice` 예산과 공유.
- 샘플 문장은 서버에서 필수(빈 값이면 422). 기본 문장은 **앱이 채운다** (Claude 결정): 기본 문장 둘(반말·존댓말) 중 하나를 앱의 기존 `isCasualSpeech`(`MorningGreeting.kt`, `ce5b716`)로 골라, 샘플 문장 칸이 비어 있으면 그 문장을 보낸다. 서버에 같은 판단을 다시 구현하지 않기 위해서다.
- 설명은 기존 `/voice/synthesize`처럼 LLM으로 중국어 번역해 instruct로 넣는다(그 코드를 옮겨 쓴다).
- 길이 검사: 결과가 8~13초를 벗어나면 다시 뽑는다, 최대 4회. 끝까지 벗어나면 시도한 것 중 10초에 가장 가까운 것을 쓴다(`gen_reference_voices.py`의 MIN_SEC·MAX_SEC·TARGET_SEC·ATTEMPTS와 같은 규칙).
- 결과를 후보 키에 저장하고, 오디오를 응답으로 돌려준다(앱이 바로 재생).
- **보석 과금이 들어갈 자리.** 생성 1회를 처리하는 함수 하나에 모은다.

주의: TTS 서버 응답은 Ogg/Opus(`_encode_audio`)다. 기준 음성은 WAV로 저장돼 왔다. 길이 측정과
기준 음성 저장에 필요한 형식은 빌더가 맞춘다(TTS 서버에 WAV 응답 옵션을 두든, 백엔드에서 디코딩하든).

### 확정 — `PUT /personas/{id}`에 붙인다 (Claude 결정)

"이 목소리로 정하기"는 앱 상태만 바꾸고, 실제 반영은 비서 저장 때 한다. 그래야 공개 심사와
목소리 반영이 한 번에 결정된다.

- `PersonaIn`에 `applyVoiceDraft: bool = False` 추가.
- `true`면 서버가 후보 json에서 설명·샘플 문장을 읽어 심사 대상에 넣는다. **앱이 보낸 텍스트가 아니라 후보에 기록된 텍스트**를 쓴다 — 실제 소리를 만든 텍스트를 심사해야 하므로.
- 후보가 없거나 `creator_uid`가 요청자와 다르면 400.
- 심사 대상: 기존(이름·소개·태그·세 칸) + 목소리 설명 + 샘플 문장. `build_moderation_prompt`의 `<persona>` 구획에 두 줄을 추가하고, 금지 항목에 "숨소리·속삭임·신음 등 비언어 발화나 성적 뉘앙스를 노린 목소리 지시"를 더한다.
- 반영 규칙:
  - 비공개 저장 → 심사 없이 후보를 기준 음성으로 승격, 컬럼 갱신.
  - 공개 저장 + 통과 → 승격, 공개.
  - 공개 저장 + 거부/실패 → 기존 규칙대로 비공개로 저장. 목소리는 **승격한다**(비공개 비서엔 문제없다). 사유 안내는 기존 그대로.
- 승격 = 후보 wav·json을 기준 음성 키로 복사(로컬·GCS 모두) 후 후보 삭제.
- `applyVoiceDraft=false`로 공개 저장할 때도 **이미 저장된** `voice_description`·`voice_sample_text`를 심사에 넣는다 (Claude 결정). 공개 거부 → 비공개(목소리는 승격) → 성격 칸만 고쳐 다시 공개하는 순서로 심사 안 된 목소리 텍스트가 공개 비서에 붙는 구멍을 막는다. 즉 심사 대상 목소리 텍스트 = 후보를 적용하면 후보 것, 아니면 저장된 것.
- 기존 "공개 비서를 같은 텍스트로 재저장하면 심사 생략" 조건에 `applyVoiceDraft == false`를 더한다(목소리를 바꾸면 반드시 재심사).
- **공개 조건:** `isPrivate=false`인데 저장 후 목소리가 없으면(기존에도 없고 `applyVoiceDraft`도 아님) 비공개로 저장하고 `moderation.status = "voice_required"`를 돌려준다. 앱은 이걸 미리 막지만 서버도 같은 조건을 지킨다.
- 응답은 기존(`ok`·`isPrivate`·`moderation`)에 `voiceDescription`·`voiceSampleText`(저장 후 값, 없으면 null)를 더한다 (Claude 결정). 앱은 이 값으로 Room을 갱신한다 — 서버가 후보에서 확정한 값이 기준이다.
- 구버전 앱은 `voice_required`를 모르는 값으로 보고 SKIPPED로 처리한다(`PersonaSaveMapping.kt`). 구버전 앱에선 목소리를 만들 수 없으니 공개 시도는 모두 비공개로 내려가며 안내가 부정확할 뿐이다 — 허용한다.

### 닫는 것

- `POST /voice/save_reference/{persona_id}` — 삭제. 앱에서 호출하는 곳이 남아 있으면 함께 지운다.
- `POST /voice/synthesize` — 삭제(새 `/voice/design`이 대체). 앱 `ApiService`의 선언도 지운다.

### 조회·노출

- 상점 미리듣기는 기존 `GET /voice/reference/{persona_id}`를 그대로 쓴다. 유저 비서도 기준 음성이 생기면 자동으로 들린다 — 동작 확인만.
- 남의 비서에는 `voiceDescription`·`voiceSampleText`를 내려주지 않는다(세 칸을 숨기는 기존 코드 경로에 함께 넣는다). 만든 사람에게는 내려준다(수정 화면 복원용).
- 후보 조회 API는 두지 않는다. 앱은 생성 응답으로 받은 오디오를 들고 있다가, 화면을 떠나면 버린다 (Claude 결정).

### 배포 시 기존 데이터 정리 (사용자 결정)

공식 비서(`creator_id = SYSTEM_CREATOR`)와 로컬 개발용 `dev_*`는 건드리지 않는다. 그 밖의 비서에 대해,
스키마 추가 직후 한 번:

1. **기존 기준 음성 파일 삭제.** 8월 이전 앱이 `/voice/save_reference`로 올린 오디오가 운영
   `reference_voices/{id}.wav`(로컬·GCS)에 남아 있을 수 있다. 알람 클로닝과 상점 미리듣기가 파일만
   있으면 쓰므로, 엔드포인트만 닫아선 "앱이 보낸 오디오가 기준 음성이 되는 경로"가 남는다.
   `voice_sample_text IS NULL`인 비서의 기준 음성 파일을 지운다. 이 비서들의 알람은 폰 기본 TTS로 돌아간다.
2. **목소리 없는 공개 비서를 모두 비공개로.** `is_private = FALSE AND voice_sample_text IS NULL`
   → `is_private = TRUE`. 신고 잠금(`report_locked_at`)은 건드리지 않는다. 만든 사람은 목소리를 만들어
   공개 저장하면 일반 심사를 거쳐 다시 공개된다.

정리 후에는 "목소리 있음" = `voice_sample_text IS NOT NULL` 하나로 판단하고, 칸과 파일은 확정 경로에서만
함께 쓰여 어긋나지 않는다. 정리 작업은 멱등이어야 한다(서버 기동 시 실행되는 기존 마이그레이션 방식에 맞춘다 — 빌더 판단).

### 삭제

비서 삭제 시 기준 음성과 후보를 함께 지운다(서버 `DELETE /personas/{id}`에서 처리, 앱 VM의 기존
`deleteReferenceVoice` 호출은 남겨도 무방).

## 앱

- Room: `voiceDescription`·`voiceSampleText` 컬럼 추가(v24 마이그레이션). DTO에도 추가. "목소리 있음" = `voiceSampleText != null`.
- `PersonaEditViewModel`: 설명·샘플 문장 입력 상태, 후보 오디오(메모리), 생성 중 상태, "정하기" 여부(`applyVoiceDraft`). 저장 응답의 `voice_required` 처리.
- 생성 실패(네트워크·500·429) 시 토스트, 정해진 목소리는 그대로.
- 오프라인 저장(기존 OFFLINE 경로)에서는 후보 적용을 버린다 (Claude 결정). 후보는 서버에 있으니 다음에 온라인으로 저장할 때 "정하기"를 다시 누르면 된다. 공개 저장 차단은 Room의 `voiceSampleText`(=서버가 확정한 값)나 이번 저장의 `applyVoiceDraft`로 판단한다.
- 재생은 기존 `VoicePreviewPlayer`를 쓰거나 바이트 재생을 추가 — 빌더 판단.
- 알람 쪽은 바꿀 것이 없어야 한다: 기준 음성이 생기면 기존 클로닝 경로가 쓰고, 없으면 기존 폴백(폰 TTS).

## 테스트

백엔드(pytest):
- `/voice/design`: 소유자 아님 403, 한도 초과 429, 빈 샘플 문장 → 기본 문장, 길이 벗어나면 재시도, 후보 덮어쓰기.
- `PUT /personas` `applyVoiceDraft`: 비공개 승격 / 공개 통과 승격 / 공개 거부 → 비공개 + 승격 / 후보 없음 400 / 남의 후보 400.
- 심사 프롬프트에 설명·샘플 문장이 들어가고 `<`·`>`가 제거되는지.
- 목소리 바꾼 재저장은 심사 생략 안 됨.
- 공개 + 목소리 없음 → 비공개 + `voice_required`.
- `/voice/save_reference`·`/voice/synthesize`가 없어졌는지.
- 남의 비서 조회에 두 칸이 없는지.
- 배포 정리: 목소리 없는 유저 공개 비서 → 비공개, 기준 음성 파일 삭제, 공식·`dev_*`는 그대로, 두 번 돌려도 같은 결과.

앱(단위): ViewModel 상태 전이(만들기→다시 만들기→정하기→저장), 공개+목소리 없음 저장 차단.
