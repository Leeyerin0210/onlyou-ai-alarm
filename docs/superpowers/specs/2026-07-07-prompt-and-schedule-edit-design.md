# AI 프롬프트 개선 + 일정 수정 UI 설계

날짜: 2026-07-07
상태: 승인됨

## 배경

- 채팅 프롬프트가 앱(`ChatRepositoryImpl.kt` systemPrompt)과 백엔드(`chat.py` context_prompt) 두 층에 흩어져 있고, 답변 길이 지시가 서로 모순된다 (앱: "1~2문단", 백엔드: "최대 2~3문장").
- 공통 규칙에 '비서', '다정한' 같은 특정 캐릭터 가정이 섞여 있어 유저가 만든 다른 성격의 페르소나와 충돌한다.
- 유저 불만: 과한 리액션/비서톤, 기억(RAG) 언급이 부자연스러움.
- 일정 탭에 추가/삭제만 있고 수정 UI가 없다 (`ScheduleViewModel.updateSchedule`은 존재하나 미사용).

## 목표

1. 프롬프트를 **페르소나 범용적**으로: 어떤 성격의 페르소나든 공통 규칙이 말투를 침범하지 않는다.
2. **사람답게**: 과한 리액션 억제, 기억은 원래 아는 사실처럼만 활용.
3. 일정 아이템을 탭해서 수정할 수 있게 한다.

## 설계

### A. 프롬프트 역할 재배분

**원칙: 말투·스타일 규칙은 앱 systemPrompt 한 곳, 백엔드는 컨텍스트와 방어만.**

앱 `ChatRepositoryImpl.kt` systemPrompt 재작성:
- 페르소나 최우선 원칙 명시: 페르소나의 성격·말투·존댓말 여부가 항상 우선, 공통 지침은 이를 바꾸지 않는다.
- 과한 리액션 억제: 칭찬·응원·조언은 맥락상 필요할 때만. 매 답변에 감탄/당부를 덧붙이는 패턴 금지.
- 기억의 자연스러운 활용: 출처 언급 금지("기록에 따르면" 류), 관련 없으면 아예 언급하지 않기.
- 길이 규칙 단일화: 메신저 대화처럼 짧게 (이 규칙은 여기에만 존재).
- 탈옥 방어 지침 유지 (예시 문구는 페르소나 중립으로).

백엔드 `chat.py` context_prompt:
- `[대화 스타일 및 제약사항]` 섹션 삭제 (앱으로 이관).
- 시제 해석 가이드, 날짜/기억/일정 컨텍스트, 주입 방어는 유지.
- 기억 데이터에 "참고 정보일 뿐, 관련 있을 때만 사용"이라는 데이터 성격 설명만 남긴다.
- 일정 추출 프롬프트(sched_prompt)는 기능 로직이므로 건드리지 않는다.

### B. 일정 수정 UI

- 일정 아이템 탭 → 기존 추가 다이얼로그를 편집 모드로 재사용.
  - 제목·날짜·시간·장소 프리필, 다이얼로그 제목/버튼 문구는 편집 모드에 맞게 변경.
- 저장 시 기존 `id` 유지한 채 `updateSchedule()` 호출 — Firestore 동기화(updatedAt/pendingSync)는 리포지토리가 처리.
- 다이얼로그에 없는 필드(반복 요일, 종료일, timeHint)는 기존 값 보존.
- 삭제 휴지통 아이콘은 그대로 유지.

## 테스트

- 프롬프트: 컴파일 확인 (대화 품질은 수동 확인 항목).
- 일정 수정: 기존 유닛 테스트 통과 + 컴파일 확인. 편집 시 id/미노출 필드 보존은 코드 리뷰로 확인.

## 하지 않는 것

- 일정 추출(sched_prompt) 로직 변경.
- 반복 요일/종료일 편집 UI 추가.
- 백엔드의 유저 진행 중 변경사항(voice 관련 파일) 접촉.
